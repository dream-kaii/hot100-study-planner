# Hot 100 算法学习平台改造设计

## 1. 目标和使用人群

项目面向第一次系统学习算法、同时准备 Java 后端面试和 AI 应用开发的用户。用户不应只得到一个题目列表和答案，而应沿着学习顺序理解常见数据结构、算法模式、复杂度和边界条件，最后能够独立完成力扣函数题和 ACM 完整程序题。

第一阶段优先保证本机使用可靠：题目、题解、代码草稿和学习状态在本地保存，Java 与 Python 在用户电脑上运行。线上静态页面可以继续部署，但没有远程执行服务时不显示“线上判题已通过”；线上代码执行作为后续可插拔能力。

本设计取代此前设计中“强制配置备份”“通用标准输入模板”“只比较第一个示例”和“题解覆盖练习区”的约定。保留 React/Vite、现有题号、可用媒体和现有学习记录；只改造学习、内容、编辑、执行和保存相关部分。

成功标准是：新用户能从第一道题开始，读懂思路、编写代码、运行公开用例、记录错误、回顾题解、继续下一题，并在刷新或重新打开项目后恢复进度和代码。

## 2. 已确认的产品约束

- 题目范围严格来自力扣 Hot 100，保留原题号、标题、难度和力扣链接。
- 题解可以参考代码随想录、力扣官方题解和高质量力扣题解，按题目实际内容选择来源。
- 每个结论、复杂度和代码都必须经过推导、样例运行和人工复核；不能用无关的通用总结填充内容。
- 题解文字和答案代码属于同一篇左侧阅读内容，代码块不再独立漂浮在另一个页面。
- 右侧是用户自己的固定编码区，切换题面/题解、语言或练习模式时不丢失草稿。
- Java 是默认主语言，Python 作为并行语言；两种语言都支持力扣函数模式和 ACM 完整程序模式。
- 第一阶段不增加账号、云同步、多用户后端，也不把用户代码上传到第三方。

## 3. 学习路径

原始 Hot 100 顺序继续保留，用于显示力扣官方顺序；项目增加独立的“学习顺序”。学习顺序按先建立工具，再学习可迁移的模式，最后进入综合题的原则编排，不简单按题号或难度排序。

### 入门准备：先知道代码在做什么

提供短小的概念卡：数组下标与遍历、函数参数与返回值、哈希表、集合、时间/空间复杂度、排序比较器、递归的终止条件。概念卡用很小的 Java/Python 示例解释，不额外扩充 Hot 100 题库。递归、堆、回溯和动态规划的概念在相应专题开始前再讲，不一次堆给新用户。

### 阶段一：数组、哈希和基础技巧

先掌握遍历、计数、映射、原地修改和前缀关系：283、1、136、169、121、49、128、238、189、56、73、54、48。136 先解释计数解法，再解释异或性质；169 先解释计数，再讲投票法的抵消不变量。

### 阶段二：双指针、滑动窗口和二分

学习有序性、区间维护和单调性：11、15、3、438、560、35、74、34、33、153、240。滑动窗口明确适用条件，560 解释为什么含负数时不能直接用固定方向收缩窗口。

### 阶段三：链表、栈和队列

先用指针和哨兵解决链表，再进入单调栈和表达式处理：206、21、141、160、19、2、24、142、234、138、20、155、394、739。

### 阶段四：树和堆

通过递归、迭代和层序遍历理解树结构，再学习优先队列、归并和双向链表：94、104、226、101、102、199、543、108、98、230、114、105、236、437、215、347、148、146。148 之前补充归并排序概念，146 之前补充双向链表的插入与摘除。

### 阶段五：回溯、图和贪心

先学状态选择与撤销，再学网格/拓扑关系，最后理解区间和可达性贪心：78、46、17、39、22、79、131、200、994、207、208、55、45、763。

### 阶段六：动态规划

从一维状态转移到二维状态、背包和序列问题：70、118、198、53、62、64、279、322、416、139、300、152、5、1143、72。动态规划逐题说明状态含义、转移依据、初始化、遍历顺序和如何获得答案，不能只给公式。

### 阶段七：综合与挑战

在前面的工具和思想已经建立后，再练：75、31、287、239、42、76、84、25、23、295、124、51、41、32、4。困难题显示具体前置题，例如 23 依赖有序链表合并和堆，84 依赖单调栈，124 依赖树的递归返回值。

上面的顺序是学习建议，不改变 Hot 100 数据本身。最终数据文件增加 `studyOrder`、`phase`、`prerequisites` 和 `concepts` 字段，并由校验脚本保证 100 道题各出现一次。

每道题在学习页显示“为什么现在学它”：例如先学哈希表再学字母异位词分组，先学二叉树遍历再学最近公共祖先。用户可以跳题，页面显示建议回看的前置题，不阻止练习。Java 是默认语言，不强制执行练习比例；Python 重写作为专题内代表题的推荐练习。

## 4. 题解内容标准

每道题的本地题解记录采用统一结构。下面是字段示意，不是已核验的来源或媒体记录；实施中必须填写真实链接、文本和已存在的图片路径：

```js
{
  id: "1",
  sources: [], // 逐条保存名称、链接、类型（官方/社区/代码随想录）、参考用途
  learningGoal: "理解哈希表如何把查找从 O(n) 降到平均 O(1)",
  prerequisites: ["数组遍历", "哈希表"],
  thinking: "...",
  bruteForce: "...", // 直观做法及其不足
  steps: ["...", "..."],
  walkthrough: ["..."], // 用小示例展示关键变量的变化
  correctness: "...", // 说明为什么不遗漏答案或产生错误答案
  pitfalls: ["..."],
  complexity: { time: "O(n)", space: "O(n)" },
  java: "...",
  python: "...",
  examples: [{ input: "...", output: "...", explanation: "..." }],
  images: [{ url: "/solutions/1/hash-map.png", alt: "...", sourceUrl: "..." }],
  acm: {
    input: "...",
    output: "...",
    examples: [{ input: "...", output: "..." }]
  }
}
```

题解必须做到：

- 先说明题目要解决的约束，再说明为什么选择某个数据结构或算法。
- 把算法拆成可执行步骤，解释关键变量和循环不变量；第一次出现“单调栈”“动态规划”等术语时用白话解释。
- 复杂度必须和代码一致。哈希表平均查找、排序、递归栈和额外数组都要单独说明。
- Java 与 Python 代码必须可编译/运行，不能残留“版本一”、Markdown 围栏或截断代码。
- 题面、示例、约束和答案互相矛盾时，以力扣题目为准，并在数据修复记录中标明差异。
- 图片只在能帮助理解指针、树、栈、状态转移或空间变化时保留；图片下方写简短说明和来源。
- 根据本题选择适合教学的可信参考，不机械绑定单一作者。优先核对力扣题面和可访问的官方题解，参考代码随想录和必要的社区题解，统一改写成适合初学者阅读的说明。自编讲解标为“本站整理”，列出真实参考；社区文章不能标为官方，未读取的链接不能作为已核对来源。
- 不把某种输入组合的示例通过当作算法正确性的证明。说明循环或递归保持什么性质，以及终止后为什么得到答案；小规模输入用独立暴力算法对照，大规模/边界输入专项测试。
- 来源访问遇到验证、登录限制或失效时，停止重复请求，使用其他可访问来源；尚未核实的关键内容不能标为已校验。媒体保留来源和作者信息；无可用图片时可绘制明确标为本站制作的简图，保证节点、箭头和步骤与算法一致。

题解数据增加自动质量门槛：不得出现通用占位总结、空白段落堆积、缺少来源、缺少示例、复杂度占位词、无法运行的代码和未经解释的公式标记。主数据以逐题文件为唯一来源，运行时与校验工具读取同一批文件；聚合文件如果保留，只能由脚本生成，不能人工维护两套不同内容。

题解的阅读顺序为：题意复述 → 直观做法 → 改进思路 → 示例演练与图 → 正确性说明 → 复杂度 → Java/Python 代码 → 易错点与可迁移思想。代码有两种语言标签，文章正文不因切换语言重复展示。段落间距紧凑而清晰，保留必要行距；列表、公式、表格和图片按内容呈现，不靠大量空行分隔。

## 5. 练习工作区

练习页采用左右双栏：左侧为固定阅读区，右侧为固定编码区。两栏独立滚动，用户调整左侧内容时右侧编辑器不移动；小屏幕改成上下排列，但编辑器状态仍然保持。

左侧包含两个标签：

- **题目**：题意、约束、示例、输入输出说明、学习目标和前置知识。
- **题解**：思路、步骤、易错点、图、复杂度、Java/Python 答案代码和来源。

右侧包含：

- Java/Python 语言切换。
- 力扣函数模式 / ACM 完整程序模式切换。
- 学习模式 / 独立模式 / 面试模拟模式切换。
- 代码编辑器、保存状态、运行按钮、自定义测试用例和逐条结果。

学习模式提供签名、分级提示和概念入口；独立模式隐藏提示但保留签名；面试模拟隐藏题解和补全，保留基本编辑能力。开始模拟不能清空已有代码：用户选择单独的临时练习副本或保留当前草稿，只有主动重置才替换草稿。

每道题保存四份草稿：`questionId + language + mode`，这里的 mode 仅指函数/ACM 格式。题解答案代码只读展示，用户代码与答案代码永远分离。编辑器采用 Monaco，按需加载，支持行号、语法高亮、自动缩进、括号匹配、查找替换、撤销重做、字号调整和最大化；不承诺未配置语言服务的 Java 语义补全。保存内容包括光标和滚动位置；切换左侧标签不重建编辑器模型，当前会话保留撤销栈，重新打开恢复草稿和位置，不承诺恢复跨会话撤销栈。

默认使用暖白页面（背景 #F7F5F0、面板 #FFFEFB）、深灰文字（#292824）和陶土橙强调色（#B65332），代码采用高对比度浅色主题。阅读区默认约 45%，编码区约 55%，支持拖动分隔线、收起阅读区和调节结果区高度；按钮必须有文字或可访问名称，所有常用操作可通过键盘完成。

## 6. 两种代码模式

### 力扣函数模式

默认模式。页面提供题目所需的类、节点定义、函数签名和必要类型，用户集中练习算法本身。运行器负责构造输入、调用函数并比较返回值。

### ACM 完整程序模式

用于笔试和面试迁移。每道题单独提供输入协议、输出协议和示例输入，用户需要自己完成 `main`、标准输入读取和标准输出。Java 默认提供 `public class Main` 外壳，Python 默认提供读取标准输入的程序结构；算法建议单独写成方法，便于从函数模式迁移。

两种模式分别保存、分别测试。页面明确标注“示例通过”“练习用例通过”“仅完成运行”“结果不匹配”和编译/运行错误，不把样例通过描述成等同于力扣隐藏测试通过。自定义用例没有预期输出时只显示实际结果，不标为通过。

ACM 输入协议由本站定义，明确标注不是力扣原始协议。数组、矩阵、链表和树使用易读的确定性格式；有节点相交、环、随机指针或指定节点的题目须显式描述关系。函数模式为每题记录类名、方法名、参数类型、返回类型及比较策略，禁止靠猜测第一段代码或运行时随意拼接输入。

## 7. 本地运行和未来线上运行

本地版本保留 Vite 中间件：每次运行创建临时目录，使用 `python3` 或 `javac/java` 执行，限制运行时间和输出大小，并在结束后删除临时文件。编译与运行分别限时（编译 10 秒、每用例运行 3 秒），输出上限 64KB。环境检测显示实际版本与缺失命令，进程启动失败能返回提示，重复运行受控。只绑定回环地址，验证请求来源、内容类型和体积，不作为远程代码沙箱。

运行器通过题型适配器处理数组、链表、二叉树和类设计题，不再要求所有题都使用同一种字符串输入格式。Python 提供必要 typing 导入和节点定义，Java 提供集合导入和节点定义；引用身份型题目必须保留对象共享关系，不只比较节点值。函数模式与 ACM 模式使用同一套题意和测试期望。

比较策略逐题定义：答案顺序不限时做结构化比较，不能只 trim 字符串；原地修改题检查修改后的结构；多解题检查答案有效性；类设计题逐操作核对；引用节点题核对节点身份；调试标准输出与函数返回值分开展示。失败用例显示输入、预期值、实际值、错误位置和耗时。

前端通过一个普通的执行函数接收请求和结果，不先引入多层适配器类：

```text
runCode({ questionId, language, mode, code, cases })
```

当前实现调用本机接口。后续由同一个函数根据执行服务能力选择远程接口，再调用隔离的代码沙箱，避免提前增加依赖。没有远程服务时，线上页面仍可阅读题目、题解和编辑代码，但运行按钮显示本地运行提示。

不采用浏览器直接执行任意 Java/Python 作为第一阶段方案：Python WebAssembly 体积和兼容性需要单独评估，Java 浏览器运行环境更复杂，不能为了线上演示牺牲本地稳定性。

## 8. 学习状态和复习

状态拆为两类：

- 学习进度：未开始、学习中、独立完成、看提示完成、看题解完成、错题、已掌握。
- 测试记录：每次运行的语言、模式、用例结果、编译/运行错误和耗时。

“看过题解”“独立完成”“复习阶段”分别记录，不能用一组互相覆盖的状态丢掉历史；题库展示易懂的派生状态。每题仅保存最近一次结果与最近 20 次练习摘要，防止输出无限增长。完成计数包含独立/辅助完成和已掌握，掌握计数另列。

完成题目后可以直接进入学习顺序的下一题。复习优先级为到期复习、错题、当前阶段未完成题、新题。复习间隔暂定 1、3、7、14 天，但复习反馈必须记录“独立做出、需要提示、仍未掌握”，不能只依赖一个完成按钮。

本地 `localStorage` 负责即时恢复，现有 JSON 文件备份作为可选增强。首次打开不应强制用户先选择备份目录；浏览器不支持文件夹权限时，应用仍可使用本地存储和手动导出。版本化迁移保留旧题目状态、笔记和计时，不默默重置损坏数据。草稿、笔记和复习记录各自有更新时间，导入提供明确的合并、覆盖和取消选项，取消不执行导入；保存失败和备份权限失效必须可见。

每日新题默认 1 道，可按时间与能力调整，复习任务和新题分别列出，不强制按固定天数刷完。计时器默认手动开始，可选正计时/倒计时，记录题目 ID 与开始时间；切题不串计时，后台再返回按时间戳修正，归零只提醒一次且不自动判定完成。题目 URL 可分享并支持刷新、浏览器前进/后退；加载失败可以重试，快速切题不得显示上一题异步加载的题解。

## 9. 校验和验收

题解和代码采用三层校验：

1. **结构校验**：100 个题目 ID、学习顺序、来源、示例、Java/Python 内容完整且无重复。
2. **执行校验**：100 道题的 Java/Python 参考解、函数/ACM 四种组合全部运行公开示例、约束内边界用例；存在合适暴力基准时追加小规模随机对照。覆盖无序多解、原地修改、浮点误差、身份节点和状态类等不同结果规则。
3. **内容复核**：对复杂度、边界条件、题型适配和来源链接进行人工复核；有歧义时以力扣题面和官方定义为准。

产品验收至少包括：

- 新用户可以从第一道学习题开始，不依赖备份权限。
- 切换题面/题解、Java/Python、函数/ACM 后，代码草稿不会互相覆盖。
- 刷新、返回题库、重新打开后，代码、笔记、计时和状态可以恢复。
- 数组、链表、二叉树、LRU 等不同题型可以用各自适合的测试适配器运行。
- 题解中的代码块与思路在同一阅读区域，右侧编辑器保持可用。
- Java 和 Python 的正确、编译失败、运行异常、超时和输出不匹配都有明确结果。
- `npm test`、数据校验脚本和 `npm run build` 全部通过。

## 10. 分阶段实现

这次本地改造按依赖顺序落实全部已确定范围：先确定题目格式、学习路径和保存迁移，接着打通各题型执行与校验，再分专题完成内容，最后完成练习工作区、复习反馈、环境提示和完整验收。可以分批开发和检查，但只有 100 道题内容、四种代码组合及学习流程全部达到门槛后，才称为本地版完成；不能将基础题型适配或学习顺序推到后续而宣称已交付。

后续阶段才评估线上 Java/Python 执行、远程隔离、费用和服务配额，不要求用户先购买云服务器，不默认承诺免费公共执行服务长期可用。

## 11. 学习闭环增强（本轮采纳）

产品验收不能只看“题目能打开、代码能运行”。学习闭环由三条原则约束：

- **渐进解锁**：提示、思路、完整步骤和答案代码逐层展示，用户卡住时有中间帮助。
- **双向可见**：系统用于调度的提示次数、是否看过答案、复习次数和薄弱点，都要在用户界面用易懂的文字呈现。
- **适度帮助**：提示降低卡住成本，但不直接替用户完成算法；用户可以在任何提示层级停下继续独立写。

### 11.1 提示阶梯

每道题最多提供四级提示：方向性问题、关键动作、完整思路、伪代码。第一级不直接给出方法名称；第二级尽量只给动作；第三级说明方法步骤；第四级只能是伪代码，不能复制后直接运行。提示内容由题解数据逐题编写，不能运行时自动生成。

`progress[questionId]` 保存 `hintsUsed`、`hintHistory` 和最近一次使用时间。用户点击“我要提示”后只解锁下一级，已经显示的提示保留。提示在普通练习和复习中都可用。

提示次数参与练习反馈，但不单独决定掌握度：一次使用提示后仍然可以在后续复习中独立通过。页面分别显示“本次用了几级提示”和“历史上是否独立通过”。

### 11.2 题解渐进解锁

题解标签内部固定为五组：

1. 这道题在考什么（`recognition`，默认展开）；
2. 思路方向；
3. 完整步骤与变量演练；
4. 正确性、复杂度和易错点；
5. Java/Python 参考代码。

第 2 至第 5 组默认折叠，必须由用户主动打开。打开参考代码时保存 `viewedSolutionCode`、`viewedAt` 和语言。看过代码不会删除之前“独立通过”的历史，只会让当前这次练习标记为“看过题解”。

### 11.3 练习历史与进步轨迹

每次开始、运行、完成和复习反馈形成精简事件，保存最近 20 次练习摘要。事件包含题目 ID、语言、模式、提示级别、是否看过代码、结果、耗时、复习间隔和时间戳；不保存无限增长的标准输出全文。

题目详情页显示练习时间线；总览页按七个学习阶段显示独立完成、提示完成、参考题解和已稳固数量；另列“需要重点关注”题目。薄弱点由本地规则计算：提示级别较高、重复练习仍未独立通过、到期未复习、看过答案后尚未独立重做。

“已稳固”定义为：完成至少一次复习间隔为 14 天的练习，并在没有提示、没有查看答案的情况下通过该题。失败或需要提示时，下一次间隔回到 1 天；已稳固题停止进入普通到期复习队列，但仍可手动重做。

## 12. 数据契约补充

题解记录必须包含以下运行和学习字段：

```js
{
  recognition: "...",
  hints: [{ level: 1, text: "..." }],
  func: {
    className: "Solution",
    methodName: "twoSum",
    params: [{ name: "nums", type: "int[]" }],
    returns: "int[]",
    compare: "unordered-array"
  },
  cases: [{ id: "basic-1", input: {}, expected: {}, tags: ["basic"] }],
  acm: { input: "...", output: "...", examples: [] },
  sources: [{ type: "official", label: "...", url: "..." }],
  images: [{ url: "...", alt: "...", sourceUrl: "...", author: "...", license: "..." }]
}
```

`examples` 只服务阅读，`cases` 只服务执行和校验。`func.compare` 使用封闭枚举：`exact`、`unordered-array`、`unordered-nested`、`float-tolerance`、`in-place-mutate`、`any-valid`、`operation-sequence`、`identity`。每个枚举必须有比较器和至少一个题目实例。

内容脚本负责结构校验、代码运行和来源字段检查；复杂度、正确性、提示是否泄露和教学质量不能假装由脚本完全判断。它们由内容会话和验收会话按固定清单逐批复核并留下报告，用户不需要逐题参与审核，只有设计方向和最终体验需要用户确认。

## 13. 并行开发边界

为避免多个会话修改同一入口造成冲突，每个开发会话必须使用独立分支或 Git worktree，并只修改计划中列出的文件。执行顺序如下：

1. **基础契约会话**：先完成状态、草稿、历史事件和数据 Schema 的纯函数与迁移；这是其他会话的共同接口。
2. **内容会话**：依据 Schema 生成学习顺序、提示、`recognition`、`cases` 和题解字段；只修改 `src/data/` 与校验脚本。
3. **提示与渐进题解会话**：只实现提示阶梯、题解折叠组件和相关纯逻辑；不修改 `main.jsx`。
4. **编辑器与本地执行会话**：只实现编辑器模型、四份草稿和本地运行器；不修改题解内容和总览页面。
5. **历史与总览会话**：只实现历史聚合、阶段进度、薄弱点和题目时间线；通过独立组件输出数据，不修改全局入口。
6. **集成会话**：唯一允许修改 `src/main.jsx`、`src/styles.css` 和路由组合；接入前面各会话的接口，修复冲突并做完整浏览器验收。
7. **验收会话**：只负责全量测试、构建、数据校验、运行器 smoke test 和文档一致性检查；发现问题回传对应会话，不直接扩大范围重构。

每个会话必须提交自己的分支并在提交信息中写明计划编号。集成会话按 1 → 2/3/4/5 → 6 → 7 的顺序合并。未完成的内容必须显示降级界面，不能因为某一批题解缺字段而白屏。
